# Phase 07-03 — UI Design Contract

> Visual and interaction contract for the NLP Integration phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (Nova) |
| Preset | base-nova (indigo base, CSS variables, Geist font) |
| Component library | @base-ui/react + shadcn/ui components |
| Icon library | lucide-react |
| Font | Geist Variable (`@fontsource-variable/geist`) |

**Notes:**
- shadcn initialized during this phase. Existing components (RegistroCard, ReportSection, Toast, etc.) use direct Tailwind classes — migrate incrementally.
- `button.tsx` generated as first shadcn/ui component. This phase does not require additional shadcn components.
- Emotion chips use Tailwind utility classes (not shadcn components) — they are pure `<span>` elements with bg/text color classes.

---

## Spacing Scale

All values are multiples of 4 (Tailwind v4 4-point scale). Enforced across all new UI in this phase.

| Token | Tailwind | Value | Usage |
|-------|----------|-------|-------|
| xs | gap-1 / p-1 | 4px | Emotion chip vertical padding (`py-1`) |
| sm | gap-2 / p-2 | 8px | Chip horizontal padding (`px-2`), chip gap (`gap-2`) |
| md | gap-4 / p-4 | 16px | Default element spacing in cards |
| lg | gap-6 / p-6 | 24px | Section padding inside cards |
| xl | gap-8 / p-8 | 32px | Layout gaps between sections |
| 2xl | gap-12 | 48px | Major section breaks |
| 3xl | gap-16 | 64px | Page-level spacing |

**Exceptions:** None. Emotion chips use `py-1` (4px) and `gap-2` (8px) — both on the 4-point scale. The original RESEARCH.md suggestion of `py-0.5` (2px) / `gap-1.5` (6px) is overridden by user decision.

## Typography

| Role | Tailwind | Size | Weight | Line Height | Usage |
|------|----------|------|--------|-------------|-------|
| Chip / Label | `text-xs` | 12px | 500 (medium)* | 1.4 | Emotion chip text, field labels (e.g. "Sensações", "Contexto") |
| Body | `text-sm` | 14px | 400 (normal) | 1.5 | Card content, preview text, metadata (date), paragraphs |
| Subheading | `text-lg` | 18px | 600 (semibold) | 1.3 | Card title (`sentimentoNome` in RegistroCard), section headings |
| Page heading | `text-2xl` | 24px | 600 (semibold) | 1.2 | Page-level titles |

*\*Weight 500 is an exception for emotion chips and field labels only. The primary declared weights are 400 (body) and 600 (headings).*

**Font family:** `'Geist Variable', system-ui, -apple-system, sans-serif` (via `@fontsource-variable/geist`). shadcn Nova sets this as default.

**PDF report:** Uses `'Helvetica Neue', Helvetica, Arial, sans-serif` at 12pt for print. No Geist in PDF (chromedp renders HTML without webfonts unless embedded).

## Copywriting Contract

This phase introduces **no new user-facing interactive elements** — no CTAs, no forms, no destructive actions. All changes are data enrichment. The contract below documents what does exist.

| Element | Copy | Context |
|---------|------|---------|
| Emotion chip content | `{emotionPrincipal}` and secondary `{emotion}` names | Values come from NLP model (pt-BR labels from `model_config.py`). Rendered inside `RegistroCard` below `sentimentoNome`. Always visible when analysis exists (even in collapsed state). |
| PDF summary heading | **"Resumo das Emoções"** | Section heading in PDF report (D-50), shows aggregate emotion frequency for the report period. |
| PDF per-registro heading | (no heading — emotions listed inline below sentimento) | Secondary chips listed below the `.sentimento` line in each report block (D-51). |
| Empty state (no analysis) | — | Graceful degradation: no chips shown when `registro.analise` is undefined (D-48). Card looks identical to pre-analysis state. No new empty-state copy needed. |
| Error state (NLP failure) | — | D-54: NLP failures are silent. No user-facing error. Checkpoint advances regardless. The registro simply won't have emotion analysis. |
| Existing behavior | "Buscando sentimento" | When `sentimentoNome` is empty, the existing placeholder still applies (unchanged from Phase 5). |

**Primary CTA for this phase:** None. No user-initiated actions — analysis is async and invisible to the user.

**Destructive actions:** None in this phase.

## Interaction & Display Contracts

### RegistroCard — Emotion Chips

| Aspect | Specification |
|--------|--------------|
| Location | Below `sentimentoNome` heading, inside the card header row |
| Visibility | Always visible when `registro.analise` exists — both collapsed and expanded states |
| When no analysis | No chips rendered (no DOM elements), card layout unchanged |
| Principal chip | `emotionPrincipal` value from analise doc, colored per emotion palette |
| Secondary chips | Up to 3 secondary emotions (filtered by `emotion !== emotionPrincipal`, sorted by score descending). Same styling but visual hierarchy via color, not size. |
| Chip layout | `flex flex-wrap` container with `gap-2` between chips |
| Spacing from heading | `mt-1` (4px) gap between `sentimentoNome` line and chip row |
| Interaction | None — chips are purely informational, not clickable |
| Accessibility | Chips are `<span>` elements with no interactive role. Their content is read by screen readers as part of the card heading text. |

### RegistroCard — Type Changes

```
RegistroDoc → RegistroWithAnalise extends RegistroDoc {
  analise?: AnaliseNlpDoc
}
```

The `getRegistros()` service method returns `RegistroWithAnalise[]`, merging `analise_nlp` docs in-memory from PouchDB.

### PDF Report — Emotion Summary Section

| Aspect | Specification |
|--------|--------------|
| Position | Between `.periodo` div and first `.registro` block |
| Heading | `<h2>Resumo das Emoções</h2>` (font-size 16pt, color #4338ca, margin-top 24px) |
| Content | Sorted list of `{Emotion, Count}` pairs showing aggregate frequency |
| When no emotions | Section is hidden entirely (`{{if .EmotionSummary}}` guard) |
| Data source | Report service fetches all `analise_nlp` docs whose `registroId` matches registros in the period |

### PDF Report — Per-Registro Emotions

| Aspect | Specification |
|--------|--------------|
| Position | After `.sentimento` line in each `div.registro` block |
| Content | Inline list of emotion names (`.emocao-chip` class) — principal + secondary |
| CSS | `display: inline-block`, `padding: 2px 8px`, `margin: 2px`, `border-radius: 4px`, `background: #eef2ff`, `color: #4f46e5`, `font-size: 9pt` (PDF-safe inline styles, not Tailwind) |
| When no emotions | Section hidden (`{{if .Emocoes}}` guard) |
