<objective>
Implement the NLP watcher: a background goroutine inside kanso-api that long-polls CouchDB `_changes`, calls the NLP gRPC service for each new registro, and stores results as `analise:{registroId}` documents. Follows TDD — tests are written alongside implementation.

**Purpose:** This is the core integration layer linking the NLP model (07-02) with existing registros. Watcher is asynchronous (per NLP-03), resilient (exponential backoff per D-53), and handles both backfill and live processing (D-41).

**Output:** `service/watcher.go` — the goroutine event loop. `watcher_test.go` — httptest-based tests. `main.go` — wiring. `client.go` — Analyzer interface.
</objective>

  <implementation>
    Follow the RESEARCH.md pseudocode and code sketches exactly. The watcher pattern mirrors `report.go`:

    1. **Add `Analyzer` interface to `nlp/client.go`** — Extract existing `Analyze` signature as interface:
    ```go
    type Analyzer interface {
        Analyze(ctx context.Context, req *AnalyzeRequest) (*AnalyzeResponse, error)
    }
    ```
    The existing `*Client` satisfies this interface by method signature. No changes to `Client` struct or methods.

    2. **Create `service/watcher.go`:**
      - `WatcherService` struct with: `mu sync.Mutex`, `couchRepo *repository.CouchDB`, `client Analyzer`, `cfg *config.Config`, `stopChan chan struct{}`, `started bool`
      - `NewWatcherService(couchRepo *repository.CouchDB, client Analyzer, cfg *config.Config) *WatcherService` — constructor, creates `stopChan`
      - `Start()` — Lock mutex, set `started=true`, launch `go s.run()`, return immediately. If already started, return nil (no-op).
      - `Stop()` — Close `stopChan` to signal goroutine to stop
      - `run()` — Private method containing the event loop:
        1. Get checkpoint: `couchRepo.GetCheckpoint()`. If nil, `since = "0"`
        2. Enter loop with select on `stopChan`:
           a. Call `couchRepo.GetChanges("registros", since)`
           b. If error, log, sleep 5s, continue
           c. For each result:
              - Check `_deleted` — skip if true
              - Parse `doc` as raw JSON, check `type` field — skip if not "registro"
              - Build `nlp.AnalyzeRequest` from doc fields (sensacoes, contexto, pensamentos, dataHora)
              - Throttle: `time.Sleep(50 * time.Millisecond)` between calls
              - Retry loop (3 attempts): call `client.Analyze(ctx, req)` with timeout context
                - Backoff: 1s, 4s, 16s
                - If success: build `AnaliseDoc`, call `couchRepo.SaveAnalise()`, break
                - If all 3 fail: log error, continue (D-54)
           d. After all results processed: `couchRepo.SaveCheckpoint(resp.LastSeq)`, set `since = resp.LastSeq`
        3. On stopChan signal: return (exit goroutine cleanly)

    3. **Wire in `main.go`:**
      After existing service setup (after line 51 `pushHandler := ...`), add:
    ```go
    nlpClient, err := nlp.NewClient(cfg.NLPGrpAddr)
    if err != nil {
        log.Printf("warning: nlp client not available: %v", err)
    } else {
        watcherSvc := service.NewWatcherService(couchRepo, nlpClient, cfg)
        watcherSvc.Start()
    }
    ```
    **IMPORTANT — nil client guard:** `nlp.NewClient` returns `(*Client, error)`. If it fails, `nlpClient` is a nil `*Client`. Wrapping a nil concrete pointer in the `Analyzer` interface produces a NON-nil interface — `s.client == nil` would NOT detect it, and `s.client.Analyze()` would panic. Therefore, the watcher is only created and started when `NewClient` succeeds (inside the `else` branch). When NLP is unavailable, the watcher is never instantiated — no panic risk, no goroutine overhead.

    4. **Create `service/watcher_test.go`:**
      Use `httptest.NewServer` to mock CouchDB _changes endpoint (following `push_test.go` pattern). Create mock `Analyzer` implementations for each test scenario. Test structure:
      - `TestWatcher_NoCheckpoint_StartsWithSinceZero` — mock GET `checkpoint:nlp_watcher` → 404, verify _changes URL has `since=0`
      - `TestWatcher_ResumesFromCheckpoint` — mock GET checkpoint → returns doc with last_seq, verify _changes URL uses it
      - `TestWatcher_ProcessesRegistro` — mock _changes returns 1 registro doc, mock Analyzer returns success, verify SaveAnalise called
      - `TestWatcher_SkipsNonRegistro` — mock _changes returns analise_nlp + checkpoint docs, verify Analyzer NOT called
      - `TestWatcher_SkipsDeletedDoc` — mock _changes returns deleted doc, verify Analyzer NOT called
      - `TestWatcher_RetriesOnError` — mock Analyzer fails 2 times, succeeds on 3rd, verify 3 Analyzer calls
      - `TestWatcher_SkipsAfterRetries` — mock Analyzer always fails, verify SaveAnalise NOT called, SaveCheckpoint called (checkpoint advances)
      - `TestWatcher_SavesCheckpointAfterBatch` — mock _changes returns 2 registros, verify SaveCheckpoint(lastSeq) called after both processed
      - `TestWatcher_RateLimitsCalls` — mock _changes returns 3 registros, verify elapsed time >= 100ms (2 gaps × 50ms)
      - `TestWatcher_Stop_ExitsCleanly` — Start then Stop, verify no hang

      **Mock Analyzer pattern:**

## Trust Boundaries

| kanso-api → CouchDB _changes | Admin credentials, internal network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Denial of Service | _changes long-poll loop | mitigate | 30s HTTP request timeout in GetChanges. Network error causes 5s sleep and retry — no crash, no leak. |
| T-03-06 | Elevation of Privilege | Watcher admin CouchDB access | accept | Watcher runs inside kanso-api with admin creds (same as existing services). No external API exposure. Analise docs include userSub for per-user isolation. |
| T-03-07 | Tampering | Infinite analysis loop | mitigate | D-39: client-side filter by doc.type === "registro". Also check _deleted. Watcher never processes its own analise_nlp docs (they have type: "analise_nlp"). |
| T-03-08 | Denial of Service | NLP gRPC service overwhelmed | mitigate | D-42: 50ms rate limit between NLP calls. 3 retries with 1s/4s/16s backoff. After 3 failures: skip silently (D-54). |
| T-03-09 | Tampering | Checkpoint race on concurrent watchers | accept | D-36 mandates single goroutine. If two instances run (redundant deploy), checkpoint would ping-pong. Acceptable for MVP D-55 semantics (at-most-once). |
| T-03-10 | Spoofing | Analise doc tampering via _changes | accept | _changes feed is read-only HTTP. Watcher never modifies registros — only creates new analise docs. |
</threat_model>
