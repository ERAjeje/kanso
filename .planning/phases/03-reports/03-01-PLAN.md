# Phase 3 - Plan 01: PDF Report Backend

## Objective
Build the Go backend for PDF report generation — db repository methods, service layer, handler, chromedp PDF generator, embedded HTML template, and Docker multi-stage infrastructure.

## Context
The Kanso PWA is an offline-first therapeutic emotion diary. Phase 3 adds async PDF report generation via chromedp. This plan covers the Go backend: CouchDB job tracking (relatorios DB), service orchestration with mutex-protected generation, chi-based API endpoints, and multi-stage Docker builds with headless-shell.

## Threat Model
- **RPT-01:** Job ownership spoofing — API must verify `sub` matches owner field before returning job data
- **RPT-02:** PDF generation resource exhaustion — mutex limits to 1 concurrent generation; `/download` does NOT consume generator
- **RPT-03:** `/download` path traversal — filepath.Join + filepath.Base restricts to PDFTmpDir
- **RPT-04:** HTML injection in report data — html/template (not template.HTML) auto-escapes
